# Handoff Report: UI/UX Redesign Strategy

## Observation
1. `index.html` contains numerous JavaScript hooks:
   - **IDs**: `gdriveUser`, `gdriveLoginBtn`, `step1`, `step2`, `step3`, `step4`, `campaignName`, `campaignCountry`, `tiktokWarning`, `totalBudget`, `exchangeRate`, `campaignObjective`, `activationsList`, `platformSplitEditor`, `splitTotal`, `planTitle`, `summaryCards`, `budgetTableBody`, `toast`, etc.
   - **Data attributes**: `data-step` on navigation buttons, `data-row-idx` on table inputs.
   - **State classes**: `.active` on `.step-btn` and `.step-panel`, `.completed` on `.step-btn`, `.hidden` on `tiktokWarning`, `splitWarning`, `toast`, and `gdriveModal`.
   - **Inline handlers**: `onclick="goToStep(1)"`, `onchange="onCountryChange()"`, `onclick="exportExcel()"`, etc.
2. `app.js` and `export.js` inject dynamic HTML that directly uses specific class names (`.activation-card`, `.asset-pill`, `.selected`, `.platform-split-row`, `.disabled`, `.subtotal-row`, `.diff-positive`) and CSS custom properties (e.g., `style="color:var(--text-muted)"`).
3. `style.css` starts with `@tailwind base; @tailwind components; @tailwind utilities;` and defines a custom `:root` dark theme palette (e.g., `--bg-base: #0A0B0F;`).
4. `<script>` tags are standard (not `type="module"`), allowing inline HTML event handlers to reference global functions like `goToStep`.

## Logic Chain
1. **Preserving Functionality**: Because `app.js` hardcodes inline CSS variables and DOM manipulation based on specific IDs and classes, we cannot blindly strip `style.css` or `index.html` tags. The `:root` variables must remain in `style.css`.
2. **Refactoring `index.html`**: Layout wrappers that are not targeted by JS (e.g., `.app-wrapper`, `.header-content`, `.form-grid`) can be entirely replaced by Tailwind utility classes directly in the HTML (e.g., `flex flex-col min-h-screen bg-[#0A0B0F] text-[#F0F2FF]`). The inline JS handlers and `data-*` attributes must be strictly retained to adhere to the interface contracts.
3. **Refactoring `style.css`**: For reusable components (e.g., `.btn`, `.btn-primary`, `.form-group`) and classes toggled or injected by JS (`.step-panel`, `.active`, `.hidden`, `.summary-card`), we must redefine them using the `@apply` directive. For example, `.hidden` becomes `.hidden { @apply hidden !important; }`, and `.btn` gets `@apply inline-flex items-center gap-2 px-5 py-3 rounded-md font-sans...`.
4. **Typography**: The fonts Inter and Space Grotesk are already linked in `<head>`. They can be integrated into the design by applying `font-sans` (configured to Inter) and a custom utility like `font-['Space_Grotesk']` for titles using `@apply`.

## Caveats
- Moving structural CSS to Tailwind utility classes in `index.html` will require a build step to compile the Tailwind CSS if arbitrary values are used, which is assumed given the existing `@tailwind` directives in `style.css`.
- The dynamic innerHTML generated by `app.js` relies heavily on `style.css` classes. Modifying these class names inside `app.js` is not allowed per the scope, so their definitions in `style.css` must be thoroughly mapped to Tailwind `@apply`.

## Conclusion
Refactor `index.html` by replacing static custom structural classes with inline Tailwind utility classes while retaining all IDs, inline handlers, and JS-toggled state classes. Refactor `style.css` by keeping `:root` variables and mapping UI component classes (especially those injected by `app.js`) to Tailwind utilities using `@apply`. This fulfills the requirement for a minimalistic, premium dark theme without breaking existing logic or converting `<script>` tags to modules.

## Verification Method
1. Compile the CSS using the project's Tailwind build process.
2. Open `index.html` in a web browser and verify the visual appearance aligns with a premium dark theme.
3. Walk through the application flow:
   - Fill in Step 1 and observe validation.
   - Ensure the country selector dynamically reveals the TikTok warning.
   - Add/remove an activation and ensure asset selection toggles correctly.
   - Generate the plan and verify the summary cards and dynamic budget table render accurately.
4. Check the browser console to confirm no CSS variable or class reference errors arise during interaction.
